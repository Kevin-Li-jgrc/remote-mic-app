# Codex / DeepSeek 前台 App 按键自动匹配测试

## 范围和状态

这是 fork 的公开源码独立实现，不使用官方私有 Plus 方案模块。仅匹配 `com.openai.codex` 和 `com.deepseek.dsh`；其他 App 除 TV 和菜单双击外使用当前基础映射。普通构建自动匹配默认关闭；隔离测试包在独立偏好域预置开启和已测 Codex 基础键位，不复制正式版数据，自定义按键仍需用户授权后启用。开启后 TV 单击全局发送无修饰 Tab，长按只发送一次 Esc，双击不执行。Codex / DeepSeek 的返回键单击退格，按住连续删除，松开停止。菜单双击切换并聚焦输入框：Codex → DeepSeek、DeepSeek → Codex；其他 App 或前台未知时 → DeepSeek。语音触发设置不变。

本机已提供隔离测试构建入口；自动化、构建和实体设备验收各自独立，未做实体遥控器验收的项目保持待验证。DeepSeek 左右默认使用公开辅助功能侧边栏导航，跨所有工作区切换 Session；已保存自定义/禁用优先。主页长按默认在当前工作区新建 Session；其他未知专属快捷键保持禁用。详见 [跨工作区导航测试](DeepSeekSessionNavigation.md)。

## 独立构建和存储边界

在功能分支执行 `SAYALL_ISOLATED_APP_MAPPING_TEST=1 scripts/package-local-test-app.sh`。脚本只生成 `~/Downloads/SayAll-AppSwitching-Test/build-N/SayAll.app`，不停止、安装或启动 App。公开构建可能不包含官方包中的组合动作、回眸增强、会员或其他私有功能。

测试包身份为 `com.kevin.sayall.app-switching-test`，偏好设置与正式版不同；应用数据位于 `Application Support/SayAllAppSwitchingTest/`，日志也使用独立目录。独立 MCP helper 根据自身所属 App 识别隔离目录。不会导入或迁移正式版用户设置；测试包基础键位根据本文已确认方案生成，所以关闭自动匹配后 TV 也保持 Tab。

单实例锁刻意沿用正式版的历史锁，防止两个版本以任意启动顺序争用硬件。测试版检测到正式版运行时提示后退出；不会替用户结束正式版。真实硬件测试前请手动退出正式版，结束测试后退出测试版，再重新打开正式版。现有驱动继续使用，不运行安装器或更改系统默认音频设备。

## 准备

1. 确认正式版配置已有备份或记录，不在正式版导入测试配置。
2. 手动退出正式版，打开隔离测试 App；系统权限确认由用户操作。新应用身份可能需要重新授予蓝牙、输入监控、辅助功能权限。
3. 测试版使用独立偏好设置，因此需在自己的首次设置流程中选择已安装的兼容麦克风，完成遥控器连接和权限步骤。不要重装驱动。
4. 在测试版启用自定义按键，再进入“APP 适配”，开启“启用 Codex / DeepSeek 自动匹配”。该开关不改基础按键映射；关闭后回到原基础映射。

## 用例与预期

| 用例 | 操作 | 预期 |
| --- | --- | --- |
| Codex 自动匹配 | 鼠标将 Codex 切到前台；按左右、确定、返回、上下、主页长按、菜单长按 | 分别发送已配置的 Codex 会话切换、Enter、退格、滚动、⌘N、⌃⇧G；一次动作一次响应 |
| DeepSeek 初始状态 | 切到 DeepSeek，单击左右；另测主页长按、菜单单击和长按 | 左右按侧边栏顺序切 Session 并请求聚焦；主页长按在当前工作区新建一次，菜单未设置动作不执行，不能泄漏 Codex 快捷键 |
| DeepSeek 专属配置 | 先用电脑键盘验证需要的快捷键，再在 APP 适配页选择 DeepSeek 并逐项设置 | 保存后只对 DeepSeek 生效，重启测试版仍保留 |
| 通用动作 | DeepSeek 前台，按确定、返回、上下、音量和主页 | Enter、退格、滚动、音量；主页仅聚焦前台输入框，不唤起 Codex |
| TV 全局 | Codex、DeepSeek、其他 App 分别按 TV | 单击只发送 Tab，不带 Command/Option/Control/Shift；长按只发送一次 Esc，不补发 Tab、不重复 Esc；双击无独立动作 |
| 未匹配 App | 切到 Safari 等应用，使用非 TV、非菜单双击按键 | 使用测试版的基础映射，不错误套用任一 App 的专属操作 |
| 菜单双击切换 | Codex 前台双击菜单，再双击菜单 | 先切到 DeepSeek 并聚焦输入框，再回 Codex 并聚焦；每次只切换一次，不夹带单击或长按动作 |
| 其他 App 进入 | 访达前台双击菜单 | 打开 DeepSeek 并聚焦输入框，不依赖最近应用顺序 |
| 菜单原手势 | Codex 前台单击菜单并等待双击窗口；再长按菜单 | 单击仍跳待处理会话（无待处理时待验证）；长按只打开一次代码审查，不切 App |
| 切换失败 | 目标 App 不可用或辅助功能权限缺失时双击 | 不发送文字或其他代替动作；不能把打开成功当作聚焦通过 |
| 目标延迟与首次语音 | 目标未启动时双击，等输入光标就绪后第一次按住说话 | 启动后聚焦；首次语音首尾完整上屏且不自动发送，不能只验证第二次成功 |
| 连续切换与取消 | 多次完成双击；两次点击之间切换前台 App | 每次完整双击只切一次；上下文变化取消旧手势，不迟到切换或发送原单击动作 |
| 返回键删字 | Codex、DeepSeek 输入框中放入可丢弃测试文字；单击返回，再按住并松开 | 单击退格一次，按住连续退格；松开即停，不发送 Esc；按住中切 App 应停止连发 |
| TV 取消 | 用电脑键盘打开 Codex 命令菜单，按住 TV 超过长按阈值后松开 | 菜单关闭，只发送一次 Esc，不切换焦点、不发送消息；按住更久不重复 |
| 关闭功能 | 关闭自动匹配后再次操作 | 所有按键包括 TV 回到测试版原基础映射 |
| 按住中切 App | 按住滚动/音量键，再用鼠标切 App | 旧动作取消，松开不补发旧动作，不留下修饰键或连发 |
| 语音回归 | 两个 App 中分别按住说话、松开，再连续重复 | 保留原 Fn 生命周期，首字尾字完整，不自动发送 |
| 正式版保护 | 正式版运行时尝试启动测试版；反向启动也验证 | 不同时接管蓝牙/HID，不自动关闭任一已运行 App |
| 配置保护 | 退出测试版后重新打开正式版 | 之前测好的 Codex 方案、TV=Tab、语音配置仍在 |

Codex 菜单单击跳待处理会话，以及审批框确定批准/TV 长按 Esc 取消，继续保留用户此前的三项待验证状态；测试包构建不代表这些场景通过。Esc 是否拒绝审批或只关闭界面，以目标 App 的真实表现为准。

## 失败判定和日志

错误应用收到专属快捷键、TV 打开 Command-Tab 切换器、DeepSeek 未设置动作却触发 Codex 功能、切 App 后继续连发、正式版映射变化、同时接管硬件，均判定失败。停止测试，不覆盖正式版配置。

设置保存日志为 `APP MAPPING phase=completed result=settings_saved enabled=true|false`；它仅证明设置保存。既有 HID/快捷键日志只能证明事件提交，目标 App 最终效果需用户观察。测试日志位于独立命名空间，不记录聊天内容。问题反馈附按键、手势、前台应用类别、发生顺序及 App 构建号，不附私人聊天或设备标识。

## 自动化验证边界

- `AppSpecificMappingsTests`：精确匹配、未知 App 回退、TV 固定、DeepSeek 安全默认值和编辑、持久化、旧不透明动作抑制、损坏配置。
- `TestBuildIsolationTests` / `IsolatedMCPPathsTests`：独立目录、启动互斥策略、独立 helper 的目录选择。
- `ApplicationInstanceGuardTests`：同一历史锁只允许一个持有者。
- 本机只有 Command Line Tools，缺少 XCTest。常规 `swift test --disable-keychain` 无法完成；使用仓库外临时清单排除唯一依赖 XCTest 的 `SupplementalSettingsIntegrationTests.swift`，其余 Swift Testing 用例执行。此排除未改入仓库。
- 所有 UI、蓝牙、权限、语音和真实遥控器用例仍需人工验收，不把静态截图、模拟事件或构建成功当作真机通过。

## 返回键 / TV 长按调整与配置保留

适用分支仍为 `codex/app-specific-mappings`，本次只调整上述两个通用动作和运行时按住模式。返回键的连发模式只在 Codex / DeepSeek 自动匹配生效时覆盖；TV 全局使用一次长按动作。普通构建开关缺失或关闭、未知 App 的非 TV、非菜单双击按键继续使用原基础映射。所有已保存基础映射、设备、权限和 App 专属快捷键不迁移、不覆写；关闭自动匹配后恢复已保存模式。全新隔离偏好域才按当前方案初始化；这不改变现有测试版偏好域。

新包使用与 Build 273 相同的测试身份和独立数据目录，按构建号存入新目录；不会覆盖旧 App。切换测试包前由用户退出旧测试版，然后启动新包。不得同时运行两个测试版本。新包由本机 ad-hoc 签名，系统可能要求重新确认权限，不能承诺权限自动延续。

此前 Build 273 用户实测通过：Codex 主页单击、语音、确定发送、左右会话、上下滚动、主页长按、TV 单击 Tab、返回 Esc、菜单长按审查、音量、电源禁用。返回 Esc 为旧行为记录，新方案替换它；其余记录不作为新包回归通过证据。DeepSeek 自动切换和专属键仍待测试。

本次自动化使用真实设置解析与交互控制器驱动按下/松开及可控时间，覆盖：返回键单击一次、持续退格、释放停止、上下文失效取消；TV 短按 Tab、长按一次 Esc 且不补发 Tab；已有按住模式优先级和设置字节保留。日志沿用 `BUTTON HOLD` 的阶段、终态、取消原因、动作计数及 `external_result=unknown`；只证明动作提交，实际删字和关闭菜单由用户观察。

## 菜单双击切换补充

在同一功能分支续作。只增加菜单双击路由和 DeepSeek 的公开启动/聚焦目标；复用 NSWorkspace 与现有辅助功能聚焦重试，不读取第三方内部数据。单击等待已保存的双击窗口，默认 300ms；长按阈值沿用原设置。关闭自动匹配恢复原菜单双击配置，不迁移或覆盖当前偏好域；其他键位保持前一候选行为。

自动化覆盖方向（含其他/未知前台）、按下/释放到一次打开和聚焦交接、双击不混入单击/长按、原单击/长按保留、激活成功后才交接聚焦、打开失败/未安装不聚焦、已有设置不重写。日志沿用 APP ACTION、APP FOCUS 和 BUTTON HOLD；打开成功只证明应用打开，输入框实际聚焦和首次语音须用户观察。

用户已确认 Build 274 的返回键单击退格和按住连删、TV 长按 Esc 无额外动作、TV 单击 Tab 正常。这些是前一构建的现场记录；新构建的菜单双击和稳定回归待确认。审批两项及菜单单击待处理会话仍待验证。

## Build 276 历史候选（用户实测未通过）

本节保留上一候选的记录，不作为当前操作流程。用户实测 Codex 上下键均不滚动；当前流程见下节“滚动恢复与手动输入优先”。

修复记录见 [按住滚动干扰应用切换](../Bugs/2026-11-15-held-scroll-interferes-with-app-switching.md)。本次仅行滚动改为指定目标进程投递；Command 按下时结束本次滚动，不重写任何键位配置。当前测试版、正式版和旧测试包保留；其他按键行为继续沿用 Build 275。

1. Codex、DeepSeek 各打开长回复，上下单击和按住应仍滚动回复区域，松开停止；整个过程鼠标不应被拉回中心。
2. 按住下键时移动鼠标并点击另一 App：必须能正常移动和点选；切换后旧连发停止，目标 App 不接着滚动，松开无补发。
3. 按住下键时在电脑按 Command+Tab：选择不应被 wheel 持续推动；选中 DeepSeek 后松开 Command，旧滚动不得恢复。松开遥控器后重新按下应立即可用。
4. 同样覆盖上键；再回归返回键删字、TV Tab/Esc、主页、菜单双击和切换后的第一次语音。
5. 观察测试版连接和权限状态：取消滚动后不能出现辅助功能权限失效，也不能因遥控器重复 held 报告恢复旧连发。若真实撤销权限，仍应停止遥控器接管。

以上任一失败都保持本项未通过。当前自动化已覆盖事件目标/修饰键、Command 尚未激活目标时取消、取消后的 HID 边沿保持及权限误报；它不替代 WindowServer、鼠标、Dock 和真实目标 App 的验收。日志收集仍从测试版“设置”中的诊断入口进行；判读 `SCROLL LINE` 的取消原因和 `HID ACTION cancelled`，不要把提交计数当作实际滚动成功。

DeepSeek 当前公开快捷键界面未列出前后 Session 切换；左右键继续保持未配置。此次仅检查此能力，不新增侧边栏导航或猜测快捷键。

## Build 277 滚动恢复候选与现场结果

[回退原因与修正记录](../Bugs/2026-11-15-codex-line-scroll-regression.md)。恢复 Build 275 的 wheel 投递方式；鼠标介入或 Command 按下时，结束本次行滚动连发。不会重写配置，旧 App 保留。首次 wheel 仍沿用旧坐标定位，不宣称光标从不变化；重点验证移动鼠标后不会被持续拉回。

1. Codex 长会话先按住上键，再按住下键，各 2 秒。鼠标保持静止时应持续滚动回复区，松开停止；若不滚动立即判失败，不继续跨 App 测试。
2. 按住下键时手动移动鼠标。预期本次滚动停止，鼠标可移到其他位置，不被后续事件反复拉回；继续按住不应恢复。松开再按应重新开始滚动。
3. 按住下键并移动鼠标，点选 DeepSeek。旧连发已取消，目标 App 不应接着自动滚动，松开不补发。反向也测试。
4. 按住下键时按 Command+Tab 选择 DeepSeek，松开 Command。应用选择不应被推到末尾；旧滚动不恢复，遥控器松开重按后恢复。上键同样覆盖。
5. 回归 DeepSeek 正常上下滚动、返回键删字、音量连发、菜单双击、TV Tab/Esc、切换后的首次语音；鼠标中断只针对行滚动，不应改变删除和音量连发。

当前只有自动化与构建范围的验证，实际滚动、光标、Dock 和遥控器尚待本包用户验收。日志 `BUTTON HOLD reason=pointer_input` 区分鼠标介入取消，其余取消日志沿用原格式。


用户在 Build 277 已确认两边正常滚动及主要按键、切 App 后首次语音等稳定流程。鼠标仍持续回到屏幕中央，原“鼠标介入即停止”预期未通过；用户同意记录为已知问题，暂不改代码，使用松开遥控器后再操作鼠标/切 App 的方式。本次只增加 DeepSeek Session 导航，原三项待验证仍保留。Build 276/277 的左右禁用及滚动计划段落为历史记录，当前导航以 [DeepSeekSessionNavigation.md](DeepSeekSessionNavigation.md) 为准。
