# Build 276 行滚动兼容性回退

## 现场与边界

用户打开 Codex 长会话，在 Build 276 按住下键不滚动；补测按住上键也无反应，排除仅在会话底部。代理通过测试版公开设置确认蓝牙、输入监控、辅助功能均已开启；只读读取系统修饰键状态，session/hardware Command 均为 false。没有修改配置、重新授权、查看 Codex 私有文件或向 Codex 注入探针。

Build 275 相同基本滚动已获用户实测通过；Build 276 更改为独立事件源并使用 `postToPid`。可以确认这组投递改变未通过 Codex 真实兼容性验收。内部丢弃位置不可见，不能断言已找到 Codex 内部根因。原单元测试仅验证构造和调用边界，无法证明目标 App 接受，不能作为真实滚动成功证据。

## 修正方案

恢复 Build 275 已实测可滚动的 HID/WindowServer wheel 投递方式与事件源，保留目标变化检查、Command 取消及“不把滚动取消当权限失效”的修复。不继续尝试未经现场验证的直接进程投递变体。

持续滚动改为让用户手动操作优先：按住连发开始时捕获鼠标输入事件计数；实际鼠标移动、拖动或点击后，结束当前行滚动连发，不在同一次按住中恢复。松开遥控器再按，开始新会话。Command 同样取消本次滚动。计数来自公开系统 API，不记录位置、窗口、设备身份或输入内容。

该方案仍沿用旧 wheel 坐标定位，不宣称第一次发送时光标完全不变化。验收目标是：正常按住可滚动，手动移动鼠标后不再被后续连发反复拉回，能够选到另一 App；Command+Tab 不再被旧连发推动。鼠标介入停止滚动是明确的新增中断语义，不能继续使用“移动鼠标时仍持续滚动”的预期。

只对重复单击/重复长按中的行滚动启用鼠标中断。返回键删字、音量连发、菜单/TV/主页手势及语音不受该计数影响，不保存新设置。

## 自动化

新增 `pointerInputCancelsOnlyTheCurrentHeldLineScroll`，先观察缺少中断入口的失败，再实现；覆盖上/下滚动取消、松开重按恢复、删除/音量不受影响。保留 Command、目标变化、取消不误报权限、重复 held 报告不重启等回归。

1270 项 Swift Testing、91 套件通过，21.641 秒，日志 `/tmp/sayall-scroll-recovery-tests.log`。本机缺 XCTest，唯一依赖文件 `SupplementalSettingsIntegrationTests.swift` 沿用仓库外临时清单排除，仓库清单未改。不能称为全部 Xcode 测试或真机通过。

日志：一次按住终态 `BUTTON HOLD ... reason=pointer_input` 表示鼠标介入取消；Command 和目标变化仍记录 `SCROLL LINE phase=cancelled` 的原因。取消日志不是可见滚动成功证明。计数只用于比较，不输出真实计数或鼠标坐标。
